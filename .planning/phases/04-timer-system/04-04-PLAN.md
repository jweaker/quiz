**Bug 1 — Countdown pause/resume jumps back (useCountdown.ts):**

The current useEffect triggers whenever `countdownRunning` changes. On resume, line 25 sets `startTimeRef.current = performance.now()` and line 26 uses `countdownDuration * 1000` as the total, which means it always counts down from the ORIGINAL duration, ignoring time already elapsed before pause.

Fix the useEffect:
1. Add `countdownRemaining` to the store selectors at the top of the hook (read it from `useTimerStore((s) => s.countdownRemaining)`)
2. When `countdownRunning` becomes true, calculate `startTimeRef` to account for already-elapsed time:
   ```
   startTimeRef.current = performance.now() - ((countdownDuration - countdownRemaining) * 1000)
   ```
   This way, if countdownDuration=60 and countdownRemaining=35 (25s already elapsed), the startTime is set back 25s so the math `durationMs - elapsed` correctly yields ~35s remaining.
3. Keep `const durationMs = countdownDuration * 1000` on line 26 unchanged -- the startTimeRef offset handles resume correctly.
4. Only reset thresholds when starting FRESH (countdownRemaining === countdownDuration), not on every resume. Use a condition: `if (countdownRemaining === countdownDuration) { thresholdsTriggeredRef.current = new Set() }`. On resume, keep already-triggered thresholds.
5. Also fix the reset handler in TimerPanel.tsx (shift+t shortcut and button onClick): change `setCountdown(countdownRemaining || 60)` to `setCountdown(countdownDuration || 60)` so reset restores the ORIGINAL duration, not the remaining time.

**Bug 2 — Countdown audio not playing (TimerPanel.tsx):**

Line 39 calls `useCountdown()` with no arguments, so `onThreshold` is never provided and audio never fires.

Fix:
1. Import `useTimerAudio` from `@/hooks/useTimerAudio`
2. Call `const { playBeep } = useTimerAudio()` inside the component
3. Change `useCountdown()` (line 39) to `useCountdown({ onThreshold: (seconds) => playBeep(seconds as 10 | 5 | 0) })`

**Bug 3 — Keyboard shortcuts [ ] \ broken (TimerPanel.tsx):**

react-hotkeys-hook v5.2.4 has a known issue (#1125) where bracket and backslash characters must use KeyboardEvent.code names instead of characters.

Fix all three useHotkeys calls:
1. Change `'['` to `'BracketLeft'` (start right team clock, line 57)
2. Change `']'` to `'BracketRight'` (start left team clock, line 62)
3. Change `'\\'` to `'Backslash'` (switch clock, line 67)

Keep the kbd labels in the JSX buttons as `[`, `]`, and `\` for display -- only change the useHotkeys key strings.
