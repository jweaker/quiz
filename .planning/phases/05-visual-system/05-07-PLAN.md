  <action>
  Rewrite useTimerAudio to use the Web Audio API instead of HTMLAudioElement. The current approach uses `audio.currentTime = 0` to restart playback, which causes choppy audio at rapid intervals (100ms tick rate) because the browser cannot seek and replay fast enough, especially with a 189KB WAV file.

  **Web Audio API approach:**

  1. Create a singleton AudioContext (or one per hook instance, cleaned up on unmount). Use `new AudioContext()` — resume on first user interaction if needed (autoplay policy).

  2. On mount (or first call), fetch and decode the tick sound into an AudioBuffer:
     - `fetch('/sounds/tick-CeyYiYf9.wav')` (or whatever the actual path is — check the existing code for the file reference)
     - `audioContext.decodeAudioData(arrayBuffer)` to create a reusable AudioBuffer
     - Cache the buffer — decode once, reuse for every tick

  3. For each tick playback, create a NEW AudioBufferSourceNode:
     - `const source = audioContext.createBufferSource()`
     - `source.buffer = tickBuffer`
     - `source.connect(audioContext.destination)`
     - `source.start(0)`
     - AudioBufferSourceNode is one-shot (fire and forget) — the browser garbage-collects after playback ends
     - This allows overlapping playback naturally (multiple sources can play simultaneously without conflict)

  4. For other sounds (alarm, warning beeps at 10s/5s/0s thresholds), apply the same pattern: preload into AudioBuffer, create new source per play.

  5. Keep the existing hook interface — whatever the consuming components call (e.g., `playTick()`, `playAlarm()`) should work identically. Only the internal implementation changes.

  6. Add a gain node if volume control is needed: `audioContext.createGain()` between source and destination.

  7. Handle AudioContext suspension (browser autoplay policy): if `audioContext.state === 'suspended'`, call `audioContext.resume()` before playing. This typically resolves after the first user click on the page.

  8. Cleanup: on hook unmount, do NOT close the AudioContext (it may be shared) but stop any active sources if needed.

  NOTE: This is a Phase 4 carryover issue. The timer audio hook was created in Phase 4 with HTMLAudioElement as a quick implementation. The jankiness only became noticeable during Phase 5 UAT when testing with the full visual system.
